# v0.5.0 設計（直接加算・補償）

**次の一手:** ローカルは memory UI で「完了」「取消済み」と在庫加算を確認。AWS は [aws-verify-v0.5.0.md](../aws-verify-v0.5.0.md)。

## 1. 在庫加算（Lambda なし・冪等）

| 項目 | 選択 | 理由 |
| --- | --- | --- |
| 手段 | SFN → `aws-sdk:dynamodb:transactWriteItems` | 要件どおり Lambda を挟まない。claim と ADD を原子的に束ね、途中失敗での「claim 済み・未加算」を避ける |
| 条件式（RESTOCK） | `attribute_not_exists(stockApplied) AND #s = :arrived` | 同じ補充で 2 回目の到着通知は TransactionCanceled → `StockAlreadyApplied`。在庫は増えない |
| 加算量 | 実行入力 `restockQty`（既定 `RestockQuantity=10`） | しきい値差分の計算は学習範囲外。検証しやすい定数 |
| 成功後 status | `COMPLETED` | 画面・履歴で終端が分かる。中間の `ARRIVAL_CONFIRMED` は claim 直前まで |

到着の模擬: 実行入力（または品目 META）の `deliveryOutcome`。`arrived`（既定）→ ConfirmArrival → ApplyStock。`not_arrived` → 補償へ。

## 2. 補償の順序

固定順（実行履歴で確認する）:

1. **CancelOrder** — `orderCancelled` を条件付きで true
2. **CancelRestockRequest** — `restockCancelled` を true し `status=CANCELLED`
3. **ReleaseLock** — 占有解放（既存どおり streamEventId 条件）

| 条件式 | 理由 |
| --- | --- |
| `attribute_not_exists(orderCancelled) OR orderCancelled = :false` | 再試行で二重取消しない。既に取消済みなら Catch して次へ進む |
| 同様に `restockCancelled` | 補充取消も冪等。失敗途中からの再開でも安全 |

入口: 注文永久失敗 / Retry 尽きた一時失敗 / `deliveryOutcome=not_arrived`。  
v0.4.0 の `CancelSkeleton`（`ORDER_FAILED` 一発更新）は、この補償チェーンに置き換えた。

## 3. 占有解放と次の補充

成功（ApplyStock または StockAlreadyApplied）も補償も、最後は **ReleaseLock**。  
LOCK が消えたあと、同じ品目でしきい値以下にすれば次の補充を始められる（v0.2 の占有条件のまま）。

## 4. ASL ガード（継続）

- すべての Catch に `ResultPath: $.error`
- `ReleaseLock` は ConditionalCheckFailed だけ Done
- ConfirmArrival が既に確認済みでも ApplyStock へ進み、二重加算はトランザクション条件で防ぐ

## 5. 画面

必須機能は増やさない。memory の「到着確認へ」は完了後に在庫が増え、状態は「完了」。注文失敗は「取消済み」。
