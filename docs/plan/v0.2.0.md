## 学習概念

要件 **3・8**（承認の一部は画面なしでも API/CLI で確認）。  
`.waitForTaskToken`、timeout 却下、条件付き書き込みによる占有/解放、起動失敗時の回復。

## 範囲

前提: [v0.1.0](v0.1.0.md) の縦1本が動くこと。

1. 補充ワークフローが承認待ちで止まる（自分または Grok Bot が呼ぶ承認 API で再開）
2. 一定時間返事がなければ却下扱い。在庫は変えない
3. 品目単位の条件付き**占有**と**解放**で、別更新や並行でも実行中は1本
4. 占有後の起動失敗・再試行でも占有が残りっぱなしにならない回復を計画する
5. 期限切れ・再送・承認と却下の競合は拒否し、状態を二重に進めない

## 非範囲（この版）

- 模擬注文、配送 Wait、在庫加算、補償（→ v0.4.0 / v0.5.0）
- 本格認証、本物通販

## 受け入れ条件（実装後）

1. 承認 API で再開できる。却下/timeout では在庫不変
2. しきい値以下にしたあと、さらに減らしても**2本目が起動しない**（占有中）
3. 期限切れ・重複送信・競合する decision は拒否され、状態が矛盾しない
4. 起動失敗や途中失敗でも占有が解放されるか、再試行で安全に復旧できる
