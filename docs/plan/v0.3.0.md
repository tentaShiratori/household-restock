## 学習概念

最小 UI から在庫更新・承認操作を行い、API Gateway（または同等）とワークフローをつなぐ。  
保護の境界（ブラウザに秘密を出さない）を学ぶ。

## 範囲

前提: [v0.2.0](v0.2.0.md) の承認と占有。

### 画面（最小）

- 在庫一覧、現在在庫の更新
- 補充リクエストの状態表示
- 承認 / 却下
- 静的 HTML + 最小 JS。凝った装飾なし
- 非負整数の入力、送信中 / 失敗 / 再読込、期限切れ・競合の表示
- 承認待ち以外の decision は UI とサーバーの**両方**で拒否
- **e2e シナリオ**（npm パッケージ `e2e`）もこの版の画面ができてから書く。いまは設定と tooling のみで、シナリオ0件の `e2e run` は公式どおり失敗する（偽の合格にしない）

### API 案（実装時に確定してよい）

| 方法 | 用途 |
| --- | --- |
| `GET /items` | 品目一覧 |
| `PUT /items/{id}/stock` | 現在在庫更新 |
| `GET /restock-requests` | 補充リクエスト一覧/状態 |
| `POST /restock-requests/{id}/decision` | 承認または却下 |

### 保護（暫定設計・未確定）

**推奨のたたき台（採用確定ではない）:** 1 人用・localhost。  
保護なしの書込 API をインターネットに晒さない。

検討する軽量案の例:

- API Gateway を IAM 保護し、localhost の Python 中継が署名して呼ぶ
- 中継は loopback と同一 origin を優先
- Origin / CSRF 対策を入れる。別 origin なら CORS を限定するが、**CORS を認証と扱わない**
- AWS 秘密・task token をブラウザ応答・HTML・URL・ログに出さない

公開配信・ログイン基盤・品目 CRUD・複雑な装飾はしない。

## 非範囲（この版）

- 模擬注文、配送 Wait、在庫加算、補償（→ 後続）
- 本物通販、本格認証、凝った UI
- この技術案を「決定済み」として実装を縛ること（**暫定提案**）

## 受け入れ条件（実装後）

1. localhost（または選んだ同等構成）から一覧・在庫更新・承認/却下ができる
2. 承認待ち以外の decision は UI・API とも拒否される
3. ブラウザ経路に task token や AWS 秘密が露出しない
4. 保護なしの書込が公開到達しない（選んだ設計の前提どおり）
