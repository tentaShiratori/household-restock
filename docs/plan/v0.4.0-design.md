# v0.4.0 設計（模擬注文・Retry / Catch・Wait）

**次の一手:** ローカルは memory UI で状態ラベルを確認。AWS は [aws-verify-v0.4.0.md](../aws-verify-v0.4.0.md)。

## 1. エラー分類（Retry と Catch）

| エラー名 | 意味 | SFN | 理由 |
| --- | --- | --- | --- |
| `OrderTransientError` | 一時的な注文失敗（決定的に 1 回目だけ） | **Retry**（Interval 1s、MaxAttempts 2）のあと、尽きれば Catch → 取消骨格 | 要件4の「一時失敗は再試行」 |
| `OrderPermanentError` | 継続失敗（決定的に毎回） | **即 Catch** → 取消骨格。Retry しない | 要件4の「続けて失敗したら別経路」。リトライしても回復しない想定 |
| その他 | 予期しない失敗 | Catch `States.ALL` → 取消骨格 | 占有を解放するため |

乱数は使わない。モードは `succeed` / `transient_once` / `permanent`（品目属性または `DemoOrderFailureMode`）。  
試行回数は RESTOCK 行の `orderAttempts` を ADD して進める（Retry でも同じ入力のまま判定が進む）。

## 2. 状態遷移（承認後）

`APPROVED` → `ORDERING` →（成功）`SHIPPING_WAIT` → Wait → `ARRIVAL_CONFIRMED` → `ReleaseLock`  
失敗時: → `ORDER_FAILED`（CancelSkeleton）→ `ReleaseLock`

在庫加算と補償の完成は v0.5.0。この版の取消は状態更新の骨格のみ。

## 3. Wait

注文成功レスポンスの `arriveAt`（ISO8601）を `TimestampPath` で待つ。  
長さは `DeliveryWaitSeconds`（検証時は短くしてよい）。SAM Local の時間挙動は本番の証拠にしない。

## 4. ASL ガード（v0.2 方針の継続）

- すべての Catch に `ResultPath: $.error`（`itemId` / `streamEventId` を残す）
- `ReleaseLock` は `ConditionalCheckFailed` だけ Done。想定外は成功終了に見せない
- 承認成功後も占有は注文〜到着確認まで保持し、終了時に解放

## 5. 画面

localhost 中継でラベル「注文中」「配送待ち」「失敗」「到着確認」を表示。  
memory では「到着確認へ」で Wait 相当を進める（AWS では SFN Wait）。
