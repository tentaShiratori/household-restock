# v0.2.0 設計（占有・承認・Streams 失敗）

**次の一手:** この採用案どおり SAM / 純関数を実装し、AWS 確認は [aws-verify-v0.2.0.md](../aws-verify-v0.2.0.md) で行う。

## 1. 占有キー

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **採用** | `pk=ITEM#<id>`, `sk=LOCK`, 属性 `entityType=LOCK`, `streamEventId`, `status=HELD` | 条件付き Put で占有、Delete（自 eventID のみ）で解放 |
| 不採用: META に `occupiedBy` | 在庫更新の Put と競合しやすい。Streams が在庫行をまた動かす | |
| 不採用: 実行 ARN だけを鍵 | 起動前失敗時に ARN が無く、占有の付け外しが曖昧 | |

理由: 品目 ID で1件だけ触れ、在庫行（`META`）と分離できる。v0.1 のキー接頭辞と共存する。

条件付き Put: `attribute_not_exists(sk) OR streamEventId = :eid`  
同じ Stream イベントの再試行は上書き可。別イベントは ConditionalCheckFailed → **起動しない**（要件8）。

## 2. 補充リクエストの状態遷移

`RECORDED` → `AWAITING_APPROVAL` → (`APPROVED` | `REJECTED` | `TIMED_OUT` | `FAILED`)

| 遷移 | いつ |
| --- | --- |
| → AWAITING_APPROVAL | waitForTaskToken 用 Lambda が token をサーバー保存したとき |
| → APPROVED | 承認 API が `approve` を受理し SendTaskSuccess |
| → REJECTED | 承認 API が `reject`、または明示却下 |
| → TIMED_OUT | SFN の Timeout（在庫は触らない） |
| → FAILED | 予期しない失敗。占有は解放 |

拒否（二重遷移なし）: 終端状態への再 decision、`AWAITING_APPROVAL` 以外への approve/reject、期限切れ後の decision。

## 3. 承認 API の保護

| 案 | 判定 |
| --- | --- |
| **採用** | HTTP API + 共有秘密ヘッダ `X-Approval-Secret`（SAM パラメータ `NoEcho`、環境変数へ）。task token は DynamoDB にだけ置き、応答・ログ・URL に出さない |
| 不採用: 無認証公開 | 要件の「最低限の保護」に反する |
| 不採用: Cognito / 本格 IdP | 本格認証は対象外。v0.3 の localhost 中継とも重い |
| 不採用: クライアントに task token を返す URL | 秘密の露出 |

パス: `POST /items/{itemId}/restock-requests/{streamEventId}/decision`  
本文: `{"decision":"approve"|"reject"}`  
v0.3 の中継は同じ秘密を署名またはヘッダで持てば揃えられる。

## 4. Streams 失敗処理

| 案 | 判定 |
| --- | --- |
| **採用** | `ReportBatchItemFailures` + `BisectBatchOnFunctionError` + `MaximumRetryAttempts`（短縮可能なパラメータ）。壊れた1件でシャード全体が無限停止しないようにする |
| 不採用: 例外でバッチ全体失敗のみ | 1件の恒久失敗でシャードが止まり続ける |
| 不採用: 失敗先 SQS まで必須化 | v0.2 の最小範囲を超える（後続で足せる） |

v0.1 の同一イベント冪等（実行名 + `RESTOCK#eventID`）は維持する。
