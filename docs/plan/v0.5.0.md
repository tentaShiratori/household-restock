# v0.5.0: 直接加算と補償

**状態:** 計画のみ。機能未実装。  
**推定:** 5〜7 時間  
**次の一手（実装時）:** Step Functions から DynamoDB への条件付き加算を冪等にし、補償順を固定する。

全体ロードマップ: [README.md](README.md)

## 学習概念

Step Functions から DynamoDB を直接更新する。  
条件付き書き込みによる冪等、補償（取消）の順序と再試行。

## 範囲

前提: [v0.4.0](v0.4.0.md) の注文・Wait・到着確認入口。

- 到着時、Lambda を挟まず Step Functions から DynamoDB へ在庫加算
- 同じ補充で二重加算しない（条件付き・冪等）
- 未着または注文失敗時: **注文取消 → 補充リクエスト取消**の順
- 補償の再試行も冪等
- 終端で品目占有を解放し、次回補充を可能にする
- 到着/未着の模擬入力はテスト入力でよい。画面の必須機能は増やさない
- 補充記録の状態保持と、在庫履歴 / CQRS を混同しない（後者は対象外のまま）

## 非範囲（この版）

- 在庫履歴テーブル、CQRS
- Map / JSONata / Express 比較、durable 実装比較、アラームの追加
- 本物の配送・決済

## 受け入れ条件（実装後）

1. 到着通知が 2 回来ても在庫加算は 1 回
2. 未着 / 注文失敗で取消経路が順に実行され、履歴で確認できる
3. 補償の再試行で二重取消にならない
4. 終端後に同じ品目で次の補充を開始できる
