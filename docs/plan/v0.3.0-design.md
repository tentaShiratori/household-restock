# v0.3.0 設計（最小画面と保護）

**次の一手:** ローカルは `mise exec -- uv run python scripts/serve-ui.py` → ブラウザで http://127.0.0.1:8765/ 。AWS 確認は [aws-verify-v0.3.0.md](../aws-verify-v0.3.0.md)。

## 1. 保護方式の比較

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **採用: localhost 同一 origin 中継** | `scripts/serve-ui.py` が 127.0.0.1 だけに bind。静的 `web/` と `/api/*` を同じ origin で出す。`APPROVAL_SHARED_SECRET` は中継プロセスの環境変数だけ。ブラウザの JS・HTML・URL には載せない | 1 人用学習に足りる。CORS に頼らない。v0.2 の `X-Approval-Secret` と整合 |
| 不採用: ブラウザに共有秘密を埋める | 画面ソース・DevTools に秘密が出る | 要件の「最低限の保護」と「ブラウザに秘密を出さない」に反する |
| 不採用: 書込 API を CORS 開放だけで公開 | Origin ヘッダは認証ではない | 保護なしの書込が公開到達しうる |

CORS は認証として扱わない。別 origin を許す構成はこの版では採らない。

## 2. 中継と API の役割

| 層 | 役割 |
| --- | --- |
| ブラウザ | 一覧・在庫更新・承認/却下。同一 origin の `/api/*` だけ呼ぶ |
| localhost 中継 | `memory`（既定）: プロセス内ストア。`aws`: デプロイ済み HTTP API へ `X-Approval-Secret` 付きで中継 |
| AWS HTTP API | `GET /items`、`PUT /items/{id}/stock`、`GET /restock-requests`、既存の decision。いずれも共有秘密必須。応答に `taskToken` を載せない |

`memory` ではしきい値以下の在庫更新で補充リクエストを 1 本だけ立て、占有を模する（Streams / SFN は起動しない）。ローカル学習と e2e 用。

## 3. 画面の約束

- 静的 HTML + 最小 JS。装飾なし
- 在庫は非負整数のみ（UI とサーバーの両方）
- 承認待ち以外は decision ボタンを無効化し、API も 409 等で拒否
- 送信中表示、失敗理由（競合・期限切れなど）、再読込

## 4. やらないこと（この版）

模擬注文、配送 Wait、在庫加算、補償、本格認証、公開静的ホスティング、凝った UI。
