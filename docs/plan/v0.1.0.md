## 学習概念

要件 **1・2・9**。DynamoDB のキー設計、Streams → Lambda、Standard Step Functions、SAM。

## 範囲

架空の**1品目**だけ（既定 ID: `toilet-paper`）。

1. DynamoDB に現在在庫としきい値を保存する（`pk=ITEM#…`, `sk=META`）
2. 手動で在庫を更新する（`./scripts/update-stock.sh`。AWS はユーザー実行）
3. DynamoDB Streams の変更で判定 Lambda が動く
4. 在庫数 **≦ しきい値**なら Standard Step Functions を起動し品目 ID を渡す
5. ワークフローは補充リクエストを DynamoDB に1件書いて終了する（`sk=RESTOCK#<eventID>`）
6. 上記を SAM（`template.yaml`）で定義する

### 判定条件

- **採用:** 在庫数 **≦ しきい値**（以下）
- 原文は「下回ったら」(`<`) だが、全体完了条件は「以下」。**全体完了条件を優先**

### データとキー

詳細と不採用案は [v0.1.0-keys.md](v0.1.0-keys.md)。要約:

| 操作 | 採用キー |
| --- | --- |
| 品目の取得 / 更新 | `pk=ITEM#<id>`, `sk=META`, `entityType=ITEM` |
| 品目か判定 | `sk=META` かつ `entityType=ITEM` |
| 補充リクエスト | `pk=ITEM#<id>`, `sk=RESTOCK#<streamEventId>` |
| 同一イベント冪等 | 実行名 + Put の `attribute_not_exists` |

### 再帰起動防止（採用理由）

Streams の FilterCriteria で `sk=META` かつ `entityType=ITEM` だけを Lambda に渡す。補充行の Put は届かない。Lambda 側でも同じ条件を再確認する。

### 同一イベント冪等（採用理由・要件8とは別）

SFN 実行名に `eventID` を含め、PutItem の sk にも `eventID` を含める。再処理では実行名衝突または条件付き Put 失敗となり、記録は増えない。要件8の「別更新でも2本目なし」は **v0.2.0**。

```
[./scripts/update-stock.sh]
      ↓
[DynamoDB: ITEM#… / META]
      ↓ Streams（ITEM のみ）
[判定 Lambda]
      ├─ 対象外 → 終了
      └─ 対象   → Standard Step Functions
                      ↓
                [RESTOCK#eventID を1件書いて終了]
```
