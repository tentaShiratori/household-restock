## 学習概念

要件 **1・2・9**。DynamoDB のキー設計、Streams → Lambda、Standard Step Functions、SAM。

## 範囲

架空の**1品目**だけ。

1. DynamoDB に現在在庫としきい値を保存する
2. 手動で在庫を更新する（コンソール / CLI / 小さなスクリプト）
3. DynamoDB Streams の変更で判定 Lambda が動く
4. 補充対象なら Standard Step Functions を起動する（品目 ID を渡す）
5. ワークフローは補充リクエストを DynamoDB に1件書いて終了する
6. 上記を SAM で定義する

### 判定条件

- **採用:** 在庫数 **≦ しきい値**（以下）
- 原文は「下回ったら」(`<`) だが、全体完了条件は「以下」。**全体完了条件を優先**し、差は意図的

### データとキー

キーはアクセスパターンを先に洗い出してから決める（実装時に確定）。

| 操作 | 必要な検索 |
| --- | --- |
| 品目の在庫・しきい値の取得 / 更新 | 品目 ID で1件 |
| Streams 変更が品目の在庫更新か判定 | レコード種別またはキー形状 |
| 補充リクエスト新規作成 | 品目 ID + 起動の一意性に使える値 |
| 同一イベント再処理で重複しない | 条件付き書き込み用の一意キー / 属性 |

単一テーブルか複数かは可逆な最小構成を実装時に選ぶ。在庫履歴・CQRS は扱わない。

```
[手動在庫更新]
      ↓
[DynamoDB: 品目（在庫・しきい値）]
      ↓ Streams
[判定 Lambda]
      ├─ 対象外 → 終了
      └─ 対象   → Standard Step Functions
                      ↓
                [補充リクエスト記録して終了]
```

## 非範囲（この版）

- **画面**（全体では v0.3.0 で入れる。この版だけの除外）

- durable 比較、本物通販、VPC/RDS、本格認証

## 受け入れ条件（実装後。いまは未達成）

1. 対象外更新では Step Functions を起動しない
2. 対象なら品目 ID 付きの補充リクエストを残す
3. 補充リクエスト記録による再帰起動をしない
4. 同一イベント再処理で補充リクエストを重複作成しない

条件4は「同一イベントの冪等」であり、全体完了の「別更新でも2本目なし」（要件8）と**混同しない**。
